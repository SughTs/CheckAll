# CheckAll

Check all of your device.

**从你遇到的问题出发，帮助你弄清电脑哪里出了异常。**

CheckAll 是一个面向个人设备、以 PC 为主的开源诊断项目。它的初衷是帮助用户排查设备上各种难以解释的问题：电脑突然变慢、网络时好时坏、程序频繁闪退，或系统无故重启。

用户选择问题的大类后，CheckAll 会在对应范围内进行检测，将分散的系统状态、配置和日志整理成可理解的诊断结果，帮助用户逐步缩小问题范围。

> **项目状态：设计阶段。** 本文描述项目愿景与计划中的能力。目前仓库仅包含项目说明，尚未提供可运行的诊断程序。支持的操作系统、技术方案与首批检测项目仍待确定。

## 核心流程

**选择问题大类 → 补充症状（可选） → 执行相关检测 → 查看报告 → 按建议继续排查**

1. **选择问题大类**：按用户感受到的现象选择，无需预先判断故障原因。
2. **补充症状**：通过可跳过的简单选项进一步缩小范围，例如“网络异常”中的“无法上网”“经常断开”或“速度慢”。
3. **执行针对性检测**：运行该类别对应的检查项，并展示检查进度、完成状态与无法执行的原因。
4. **查看诊断报告**：说明发现的异常、判断依据、可能原因，以及下一步建议。
5. **继续排查**：证据不足时，引导用户补充信息或执行进一步检查；需要扩大检测范围时说明原因。

## 计划中的问题类别

以下为初步分类，具体检测项将随开发逐步完善，并不代表当前已支持。

| 问题大类 | 典型现象 | 计划检查的方向 |
| --- | --- | --- |
| 运行缓慢与卡顿 | 开机慢、操作迟钝、游戏掉帧 | 资源占用、启动项、存储空间、电源设置 |
| 网络与连接异常 | 无法上网、连接不稳定、下载慢 | 网络接口、IP 配置、DNS、连通性与延迟 |
| 程序运行异常 | 无法启动、闪退、无响应 | 程序错误日志、运行依赖、兼容性与权限 |
| 系统崩溃与稳定性 | 蓝屏、死机、意外重启 | 系统事件、崩溃记录、驱动与硬件相关线索 |
| 显示与声音异常 | 黑屏、闪屏、没有声音 | 输出设备、驱动状态、显示与音频配置 |
| 存储与文件异常 | 空间异常、文件无法读写 | 磁盘容量、可用健康信息、文件系统与权限 |
| 外设与设备连接 | 键鼠、USB 或蓝牙设备无法使用 | 设备识别、连接状态、驱动与相关服务 |
| 不确定问题类型 | 难以描述或无法归类 | 通过简单问题引导分类，必要时进行基础检查 |

问题类别用于组织排查流程，不代表故障原因彼此独立。同一个检查模块可以服务于多个类别，例如存储空间不足既可能造成运行卡顿，也可能导致程序运行异常。

## 诊断报告应当回答什么？

- **检查了什么？** 展示实际执行的检查项及其结果。
- **发现了什么？** 描述异常现象，并提供相关指标、配置或日志作为依据。
- **能得出什么结论？** 区分已确认的异常、可能的原因和仍待验证的推测。
- **下一步怎么做？** 提供可操作的建议，说明操作目的及可能影响。
- **还有哪些未知？** 明确标记未执行、无权限、执行失败或当前平台不支持的检查。

“未发现异常”仅表示本次检查范围内没有找到明确问题，不等于设备完全正常。

## 设计原则

### 从症状出发

使用普通用户能理解的问题分类和描述。用户不需要先理解驱动、服务或系统日志，才能开始排查。

### 先诊断，再修复

默认以读取和分析为主。涉及系统配置修改、服务重启或其他会影响当前使用状态的操作，应先说明目的、影响及恢复方式，由用户决定是否执行。

### 结论有依据

检查结果应当可以追溯到具体证据。检测到异常不等于已经证明根因；证据不足时明确说明，不把猜测写成确定结论。

### 优先保护隐私

优先在本机处理诊断信息。报告导出或分享前应支持预览和敏感信息脱敏，例如用户名、本地路径和网络标识。任何需要向外部服务发送诊断信息的能力，都应清楚说明发送内容并征得用户同意。

### 检测能力可扩展

将检查项设计为可复用模块，明确适用平台、所需权限、检测范围和结果含义，让不同问题类别可以组合使用，也便于社区逐步贡献新的检测能力。

## 初步开发路线

- [ ] 明确首个支持的操作系统与运行方式。
- [ ] 确定首批问题类别及每类的最小检查集合。
- [ ] 定义统一的检查结果与诊断报告格式。
- [ ] 实现“选择类别 → 执行检查 → 查看结果”的最小可用流程。
- [ ] 用可复现的故障场景验证检测结果，减少误报和漏报。
- [ ] 逐步补充检测模块、报告导出与脱敏能力。

首个版本优先验证分类检测流程的实用性，后续根据实际问题反馈扩展覆盖范围。

## 参与项目

欢迎通过 [Issues](https://github.com/SughTs/CheckAll/issues) 讨论需求、补充故障场景或提出设计建议。项目进入实现阶段后，也欢迎贡献检查模块、文档和测试案例。

描述问题时，建议提供：

- 设备与操作系统的基本信息。
- 出现了什么现象，以及发生的频率。
- 触发步骤或发生前后的变化。
- 已尝试过的排查方式及结果。

提交前请检查内容，避免公开密码、令牌、个人文件或未经脱敏的完整日志。
