# CheckAll

Check all of your device.

**先获取本地证据，再由 AI 引导解决设备问题。**

CheckAll 是一个面向个人 PC 的开源诊断助手。用户选择问题大类并描述具体症状后，程序采集相关本地信息，由 AI 分析证据、提出问题、请求补充检查并给出处理方案，最后验证原有症状是否改善。

例如，“Edge 无法浏览页面，但其他应用可以联网”不能仅靠通用网络检查解释。CheckAll 希望围绕具体应用、错误信息和检查结果动态调整排查方向，而不是为每一种故障预写完整流程。

> **项目状态：设计阶段，尚无可运行版本。** 已确定 Windows 优先、C# + .NET、WPF 桌面界面的技术方向。下述能力均为计划，具体 Windows 版本、.NET 版本、模型服务和首批工具仍待选定。

## 工作流程

**描述问题 → 本地初步采集 → 脱敏与授权 → AI 分析 → 补充检查或提问 → 确认并处理 → 验证效果**

1. **描述症状**：选择类别，使用自然语言描述现象、错误提示及已尝试的方法。
2. **采集证据**：按问题范围读取必要状态、配置和日志，不默认扫描整台电脑。
3. **AI 引导排查**：分析证据，说明下一步要验证什么，按需追加检查或询问用户。
4. **受控处理**：展示方案、影响和恢复方式；需要修改系统时先取得用户确认。暂不支持自动处理的步骤提供手动指导。
5. **验证效果**：重新采集相关状态，并请用户确认原来的症状是否消失；操作成功不等于问题解决。

类别只确定初始范围。运行卡顿、网络连接、程序运行、系统稳定性、显示声音、存储文件和外设连接是计划中的入口，也提供“不确定问题类型”。具体工具会逐步实现。

## 四个核心模块

| 模块 | 职责 | 技术方向 |
| --- | --- | --- |
| 界面 | 问题输入、诊断对话、进度、证据、确认和反馈 | C# + WPF，XAML 描述布局 |
| 数据收集 | 系统与应用信息采集、诊断探测、整理与脱敏 | C# + .NET / Windows 系统接口 |
| AI 分析 | 症状理解、假设管理、动态检查计划、方案与解释 | C# + 模型 SDK 或 HTTP API |
| 处理执行 | 请求校验、获准操作、变化记录、恢复与验证衔接 | C#，少量预置 PowerShell 脚本辅助 |

共享核心层负责数据结构、接口、会话状态和调用预算，不作为第五个业务模块。建议工程名为 CheckAll.Desktop、CheckAll.Collection、CheckAll.AI、CheckAll.Execution 和 CheckAll.Core。

界面和 AI 模块保持普通权限。需要管理员权限的操作由按需启动的独立辅助进程执行，其实现语言仍为 C#。首版不执行模型生成的任意命令或脚本。

## AI 与本地工具的边界

AI 请求调用已注册的工具，本地程序校验工具名称、参数、范围、权限及授权后执行，并返回真实结果。AI 不直接控制系统。

本地规则负责明确条件检查与请求约束；AI 负责结合症状和证据动态推理。日志、网页片段等采集内容仅作为数据，不得成为绕过工具权限的指令。

模型不可用时保留已有证据和基础检查结果，允许恢复会话，并明确提示 AI 诊断尚未完成。首版计划接入云端模型 API，保留模型适配接口；本地模型支持属于后续评估项。

## 隐私与可信诊断

- 先在本地筛选和脱敏，再由用户预览并授权发送必要证据；告知模型服务、用途及可能产生的 API 费用。
- 不默认采集密码、令牌、Cookie 或与问题无关的个人文件内容；API 密钥不进入日志、报告或仓库。
- 在用户授权范围内执行只读检查；扩大范围或改变操作影响时重新说明。系统修改需要具体方案确认。
- 区分事实、可能原因与未知项，结论关联证据；不虚构检查结果。
- 报告记录失败、跳过、取消和超时。“未发现异常”仅适用于本次检测范围。
- 限制诊断轮次、工具调用和超时；没有新证据或达到预算时停止并说明局限。
