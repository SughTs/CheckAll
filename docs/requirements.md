## 1. 目标与定位

CheckAll 是面向个人 PC、先获取本地证据再由 AI 引导解决问题的诊断助手。问题大类仅提供初始范围；具体症状、采集证据与用户反馈驱动后续排查。

代表性场景：“Edge 无法浏览页面，但其他应用可以联网。”系统需要澄清影响范围和错误信息，提出可验证假设、请求相关检查、根据结果调整方向，并验证处理效果。此示例不代表已确定根因，也不是固定决策树。

成功标准是形成可追溯的诊断与验证过程，不承诺解决所有问题。采集完成、模型回复完成和操作成功均不等于问题解决。

## 2. 已确定方向与待决策事项

### 2.1 已确定方向

- 四个业务模块：界面、数据收集、AI 分析、处理执行。
- AI 是首版核心分析与调度组件；本地规则和工具负责事实采集、明确条件判断与执行约束。
- Windows 优先的桌面软件，统一使用 C# + 现代 .NET；界面采用 WPF + XAML。
- 数据收集使用 .NET / Windows 系统接口；AI 使用模型 SDK 或 HTTP API。
- 处理执行使用 C#，必要时辅以少量经过审查的预置 PowerShell 脚本。
- 高权限操作使用独立辅助进程，界面和 AI 不整体提权。
- 采用 Apache License 2.0，项目文本资料集中保存在 docs。

### 2.2 待决策事项

| 事项 | 状态或约束 |
| --- | --- |
| Windows 版本、CPU 架构及 .NET 版本 | 实现前确定 |
| 首个模型服务、模型与 SDK | 首版接入云端 API；具体供应商待选 |
| API 密钥及费用承担方式 | 告知用户费用；不在客户端内置共享秘密密钥 |
| AI 抽象库 | Microsoft.Extensions.AI 为候选，不是既定依赖 |

| 会话持久化、导出格式和保存期限 | 待确定，不默认长期保存原始日志 |
| 安装、发布、更新与脚本交付方式 | 待确定 |
| 本地模型及其他操作系统 | 后续评估；WPF 本身仅支持 Windows |

## 3. 核心流程与范围

1. 用户选择类别并自由描述症状，补充错误提示、影响范围和已尝试的方法。
2. 程序按初始范围采集必要信息，显示检查目的、进度和局限。
3. 本地筛选、整理和脱敏；用户预览必要证据并授权发送给指定模型服务。
4. AI 分析证据，提出假设、问题或结构化检查请求。
5. 本地校验请求，在授权范围内执行只读检查并反馈结果；扩大范围时说明并取得授权。
6. AI 提出处理方案。程序展示具体变化、影响与恢复能力，用户确认后执行；未实现的操作提供手动指导。
7. 再次采集相关证据，并通过用户反馈确认症状是否改善。
8. 达到结论、用户取消、无进展或触及预算时停止，汇总证据与未知项。

初始类别包括运行卡顿、网络连接、程序运行、系统稳定性、显示声音、存储文件、外设连接和不确定类型。类别可共享工具，不限制 AI 只能使用固定序列。

首版包含云端 AI 分析、基础采集与脱敏、动态检查、有限的受控处理和效果验证。暂不包含无人值守修复、任意模型脚本执行、常驻监控、第三方插件动态加载与跨平台发行。报告导出可后续迭代。

## 4. 模块边界与技术组织

| 业务模块 | 工程 | 语言与技术 | 职责 |
| --- | --- | --- | --- |
| 界面 | CheckAll.Desktop | C#、WPF、XAML | 描述、对话、进度、证据、授权与反馈 |
| 数据收集 | CheckAll.Collection | C#、.NET / Windows API | 只读采集、诊断探测、系统适配、整理与脱敏 |
| AI 分析 | CheckAll.AI | C#、模型 SDK / HTTP API | 上下文、假设、下一步计划、解释与处理建议 |
| 处理执行 | CheckAll.Execution | C#、少量预置 PowerShell | 操作校验、授权检查、执行、记录与恢复 |

CheckAll.Core 为共享基础层，定义数据契约、会话状态、调度接口及预算，不新增第五个业务模块。不在界面内直接访问系统，不在 AI 层直接执行操作。

只读检查由数据收集模块执行；会改变系统或应用状态的动作由处理执行模块负责。共享调度能力管理两类任务的超时和取消，避免模块重复承担职责。需要提权的部分另设 C# 辅助进程。

## 5. 功能需求

保留 0.1 的 FR 编号并调整对应职责，新增 FR-09 至 FR-14。

| 编号 | 归属 | 功能要求 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 界面 | 类别、自然语言症状、错误提示与补充回答 | 具体应用问题可完整表达，不强制只选预置症状 |
| FR-02 | AI / Core | 根据证据动态提出检查计划 | 下一步说明要验证的假设；条件不同时产生有意义的不同计划 |
| FR-03 | Collection / Core | 检查调度、依赖、超时、取消与去重 | 单项失败不阻断独立检查；依赖缺失明确跳过；取消不再调度新任务 |
| FR-04 | 数据收集 | 范围化采集、标准证据与来源时间 | 不默认全盘扫描；失败不记为正常；证据可追溯 |
| FR-05 | 数据收集 | Windows 系统适配与能力发现 | 无权限和不支持明确区分，不伪造数据 |
| FR-06 | AI | 症状理解、假设维护、证据解释 | 结论引用证据；未知与冲突明确标记；本地规则不能被模型覆盖 |
| FR-07 | 界面 | 展示诊断记录、建议和最终结果 | 事实、假设、操作结果与解决状态分别展示 |
| FR-08 | 界面 / Collection | 后续支持报告预览、脱敏与导出 | 实际导出与预览一致，失败有提示 |
| FR-09 | 数据收集 / 界面 | 模型发送前筛选、脱敏及授权 | 展示目标服务和必要数据；拒绝发送后仍可查看本地结果 |
| FR-10 | AI / Core | 模型适配、预算与故障处理 | 超时、限流、网络或认证失败保留证据；有界重试，不无限循环 |
| FR-11 | AI / Execution | 结构化请求校验 | 未注册工具、越界参数、过期授权与任意脚本请求均被拒绝 |
| FR-12 | 处理执行 | 明确方案确认、执行记录和可用恢复 | 实际参数与确认方案一致；记录前后变化；不可恢复时提前说明 |
| FR-13 | 全模块 | 操作后检查与症状确认 | 操作成功不自动标记解决；手动处理后也可继续验证 |
| FR-14 | Core | 会话上下文与状态管理 | 保存本次症状、证据、假设、授权及操作历史；恢复时重查过期状态 |

### 5.1 会话与工具执行

会话状态至少区分采集中、等待发送授权、分析中、等待用户补充、等待操作确认、执行中、验证中、暂停、结束和取消。解决状态单独区分已验证解决、用户反馈解决、未解决和无法确认。

每次追加检查说明目的及与既有证据的关系。没有新证据时不重复相同工具；修改系统后允许为验证而重新检查。限制轮次、工具次数、并发、时长与模型费用预算，达到限制后停止并解释。

一项检查失败后继续独立检查；依赖必要证据的检查跳过。取消后停止新调用，对无法立即中止的动作显示真实状态。修改操作不得因网络重试而重复执行，使用操作标识和执行记录核对结果；结果未知时先查状态。

### 5.2 处理与权限

在普通权限下运行界面和 AI。辅助进程只接受注册操作与经过校验的参数，并验证调用来源及对应授权，不暴露任意命令执行入口。

系统修改前展示目标、具体变化、影响、恢复方法及不确定性。用户拒绝后不执行，可以继续其他检查或手动指导。工具参数变化或原状态改变导致方案不再适用时重新确认。

首版仅自动执行已实现的有限操作。可恢复操作应保存必要的原值；恢复失败明确记录。AI 建议不构成用户授权。PowerShell 脚本来自预置受审查内容，输入经过验证，不接受模型拼接的脚本。

## 6. 数据契约

| 对象 | 最低内容 |
| --- | --- |
| 问题描述 | 会话 ID、类别、症状、影响范围、用户补充和已尝试动作 |
| 工具定义 | ID、版本、用途、平台、参数结构、权限、读写影响、依赖、超时与取消能力 |
| 检查请求 | 请求 ID、工具 ID、参数、目的、关联假设、采集范围 |
| 证据 | 证据 ID、来源、工具版本、采集时间、适用范围、执行状态、事实及错误原因、脱敏标记 |
| 诊断判断 | 判断 ID、类型、证据引用、模型与提示版本、解释、局限及下一步 |
| 处理方案 | 操作 ID、参数、证据依据、前置条件、目标变化、影响、恢复能力和确认状态 |
| 执行结果 | 操作 ID、时间、真实状态、前后变化、错误、恢复结果及验证请求 |
| 会话 | 历史、当前状态、授权范围、预算消耗、未决假设及解决状态 |

执行状态：待执行、执行中、完成、失败、跳过、取消、超时。发现情况：未发现异常、发现异常、无法判断。两者分开，不能用采集失败证明设备正常。

检查证据和用户陈述要标注不同来源。结论检查证据时效性、冲突与适用范围；不使用未经校准的概率数字。过期证据不可直接用于当前修改授权。

## 7. 非功能需求

| 编号 | 要求 | 验收方向 |
| --- | --- | --- |
| NFR-01 | 最小权限与受控修改 | 检查默认只读；提权限于必要操作；拒绝不使整体流程失效 |
| NFR-02 | 最小采集与授权发送 | 本地先筛选脱敏，告知服务与用途，在授权范围内发送 |
| NFR-03 | 秘密保护 | 不默认采集密码、令牌、Cookie；API 密钥不进入日志、报告或仓库 |
| NFR-04 | 故障隔离 | 工具或模型失败保留已有结果，限制重试，修改不重复执行 |
| NFR-05 | 响应性与预算 | 不阻塞界面，限制并发、轮次与费用；具体指标实现前确定 |
| NFR-06 | 可维护性 | 四模块接口分离，数据格式有版本，模型可适配，Windows 细节不泄漏到 AI 层 |
| NFR-07 | 可理解性 | 显示检查目的、证据、局限和影响，不仅靠颜色表达状态 |
| NFR-08 | 可测试性 | 模拟系统接口与模型回复，以可复现故障验证证据与工具选择 |
| NFR-09 | 不可信输入隔离 | 日志、网页片段和模型输出作为数据，不得绕过授权、工具注册或参数校验 |

网络探测声明访问目标，不附带发送诊断日志。模型密钥采用受保护的配置存储，具体机制实现前确定。会话持久化与保存期限未定，不默认长期保存原始日志。模型不可用时仅提供已有本地结果，明确 AI 诊断未完成。

## 8. 首版交付与验证路线

1. 确定 Windows/.NET 版本、模型配置方式和首批工具。
2. 定义共享契约、会话与权限机制，用模拟工具和模型跑通流程。
3. 实现范围化采集、脱敏预览及模型连接。
4. 实现结构化工具调用、动态计划、预算与异常处理。
5. 加入少量可控操作和手动指导，完成操作后验证。
6. 用具体应用故障进行端到端验证，再扩展类别与报告导出。

浏览器示例需区分“用户认为网络正常”和实际证据，按需询问其他浏览器、同一目标页面、错误提示与影响范围。工具可检查相关接口、配置或日志，但不预定某项配置必然是根因。单一探测目标不可达不证明设备断网。

## 9. 整体验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 用户描述 Edge 故障 | 保留应用与范围信息，采集相关证据并动态排查 |
| AC-02 | 本次检查无异常 | 仅说明当前范围内未发现异常，不宣称设备正常 |
| AC-03 | 注入已知故障 | AI 引用实际证据提出可验证方案，不虚构数据 |
| AC-04 | 无权限、失败或超时 | 继续独立检查，报告缺失证据和局限 |
| AC-05 | 用户取消 | 停止新调用，保留已完成记录，真实展示尚未停止的操作 |
| AC-06 | 工具或平台不支持 | 明确拒绝，不伪装成功 |
| AC-07 | 单一探测目标不可用 | 不直接断言设备断网 |
| AC-08 | 后续导出报告 | 默认脱敏，预览与导出一致 |
| AC-09 | 证据不足或冲突 | 标记未知，提出有区分力的检查或停止说明 |
| AC-10 | 用户拒绝模型发送 | 不发送数据，本地结果仍可查看 |
| AC-11 | 模型认证失败、限流或断网 | 保留会话，有界重试并提示，不伪报分析完成 |
| AC-12 | 模型请求任意脚本或越界工具 | 本地拒绝且不产生系统修改 |
| AC-13 | 用户拒绝或方案参数变化 | 不执行未确认的新方案 |
| AC-14 | 操作完成但症状仍存在 | 标记未解决，更新假设，不重复无效处理 |
| AC-15 | 达到预算或连续无进展 | 停止循环并提供现有证据和局限 |
| AC-16 | 日志包含指令式文字 | 作为数据处理，不触发越权调用或泄密 |
| AC-17 | 修改结果未知或恢复失败 | 不盲目重试；核对状态，记录并说明实际结果 |
